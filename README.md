For this lab I sorted the same array of 10,000 unique integers three ways: with a C++ native plugin, with a C# managed plugin, and with a C# method inside a Unity MonoBehaviour. The C++ native plugin was the fastest at 0.684 ms. The C# managed plugin took 1.836 ms and the MonoBehaviour took 1.901 ms, so the native plugin was roughly 2.7 times faster than either C# version. The two C# methods were nearly identical, which makes sense because both call the same Array.Sort function and only differ in where the code lives. The native plugin is likely faster because it is compiled directly to machine code and does not run through the managed runtime, and the C++ standard library sort is highly optimized. The difference here is under two milliseconds, so it would not matter for a single sort, but in a larger project with hundreds of heavy functions running every frame, savings like this could add up. One limitation is that I measured a single run, and the first call into a plugin can include one-time setup costs, so a few repeated runs would give a more reliable comparison. I also found that native plugins take more setup (building a separate DLL for the right 64-bit platform and matching names exactly), which is a tradeoff against the speed.
